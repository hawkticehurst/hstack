# Plain

Say it again so a smart person who is new to the topic understands it on the first read. Restate your last answer, or the thing the user named.

- Start with what it means for the user: What happened, and what they need to decide or do.
- Use short sentences, one idea each.
- Swap jargon for everyday words. When a term cannot be avoided, such as a setting name or a command, say what it is in a few words the first time.
- Give one concrete example.
- Add no new information, opinions, or caveats. If you notice the original was wrong, say so in one line at the end.
- Make it shorter than the original. Leave out paths, hashes, and code unless the user needs them to act.

No headings. A short paragraph or a few bullets.
